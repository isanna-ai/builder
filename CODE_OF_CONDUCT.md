# Code of conduct

## The short version

Be decent. Argue with the work, not the person.

## What that means here

This project is deliberately adversarial about **code** — `CONTRIBUTING.md` promises you a review
whose job is to find the way your change is wrong, and calls that a feature. That posture applies
to the artifact and never to the author. "This gate fails open when the queue is empty" is the
review working. "You clearly did not read the contract" is not.

Concretely, expected of everyone taking part:

- **Critique the change, and say why.** A finding with a file, a line, and a failure scenario is
  useful. A verdict without one is noise.
- **Take a correction well.** Being shown wrong is the fastest part of the process, not a loss.
- **Assume competence.** People come to this project from different languages, stacks and
  timezones. Ask before concluding someone did not think.
- **Do not make it personal.** No harassment, no insults, no demeaning comments, and nothing
  about someone's identity, background, or personal circumstances.
- **Do not publish other people's private information.**

## Scope

This applies in issues, pull requests, commit messages, code review, and anywhere else someone is
representing the project.

## Enforcement

Report a problem privately through GitHub: **Security → Report a vulnerability** on this
repository opens a private advisory only the maintainers can see, and it works for conduct reports
too. (The commit history here is a squashed export with a synthetic author identity, so there is
no useful address to write to.) Reports are handled in confidence.

Maintainers may edit or remove comments, close a thread, or block an account, and will say what
was removed and why. A first response is normally a warning; a pattern, or a single serious
incident, ends participation.

Maintainers are held to this document too. A maintainer who does not follow it should be reported
the same way.
